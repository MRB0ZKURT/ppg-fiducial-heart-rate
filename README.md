# PPG fiducial and heart rate revision software

This repository mirrors the versioned Zenodo archive. Download `software_release_v0.2.0.zip`, extract it into a new folder, and run the commands below from that extracted folder. The full source tree, configurations, dependency lock and scripts are inside the ZIP.

Version 0.2.0. Software DOI: https://doi.org/10.5281/zenodo.24047810. Source repository: https://github.com/MRB0ZKURT/ppg-fiducial-heart-rate. It accompanies “PPG fiducial choice and the incremental value of heart rate for pulse timing prediction”.

## Which results are current

Use `python scripts/reproduce_revision.py --mode full` from this directory. The final primary results are in `revision/results/stage2_quality_consistent`; signal sensitivities are in `stage3`, and native CSV comparisons in `stage4`. The `outputs/algorithmic_v2_2026-09-06` directory and `stage2` intermediate results reproduce historical processing to document the correction. They are not the final revised estimates. Legacy `senssmarttech analyze`, report and CSV-sensitivity commands alone do not reproduce the revision.

The original source modules are retained for reproducible provenance. Mandatory revision scripts correct RR masking, require both detected feet before inter-site differences, and enforce matched outcome quality/minimum-beat rules for the native CSV comparison. The filter itself was not changed: it is a Hamming-windowed sinc FIR applied forward and reverse, not fourth-order Butterworth. The configuration's old `order` key is unused. The legacy RR-deviation fraction setting is also unused; it must not be interpreted as an additional applied beat-rejection rule. These implementation details are stated explicitly rather than silently changing numerical processing.

## Setup and source data

Use Python 3.12. Install with `python -m pip install -c requirements-clean.lock -e ".[full-stats,external-validation]"`. The lock records the dependencies of the independently tested clean installation; `environment-tested.txt` records the earlier development environment. Other Python or dependency versions have not been validated. Obtain SensSmartTech v1.0.0 under `Dataset` with `python scripts/download_senssmarttech.py Dataset`, subject to its own licence. See THIRD_PARTY_DATA_NOTICE.md. No downloads occur automatically during analysis.

Run `python scripts/reproduce_revision.py --help` for modes. Full mode regenerates primary historical intermediates, then applies the revision and runs sensitivities. Cached mode requires the historical CSV intermediates under the documented output directory; it does not claim raw-data end-to-end reproduction. Verify mode checks existing revised outputs. The runner fails on errors and records completed stages.

## Scope and limitations

- 32 participants; repeated records are not independent people. Primary performance weights participants equally.
- Method selection repeats within outer training participants; it does not repeat within each inner tuning split.
- Prediction confidence intervals use 5,000 paired participant resamples and condition on fitted predictions. Method selection retains the historical 2,000-replicate rule. Candidate comparisons are exploratory.
- Singular generic unconditional mixed fits must not be reported. Use the independently checked profile-REML ICC file; accepted conditional models are flagged separately.
- HR-only versus intercept-only is distinct from added HR benefit beyond activity and elapsed recording time. Within-person normalization is distinct from absolute prediction.
- Filter sensitivities hold R detections fixed. The signed inter-site difference is not physiological transit along a single measured path.
- Historical QTDB results are not regenerated by the revision runner. The six-person historical pilot has a separate reproduction script (below); all archived tables and criteria were matched exactly from raw recordings. The retained legacy tangent primitive is used with a reconstructed fixed-window wrapper; the complete old source file was not recovered. This does not validate the final prediction models. External participant selection was a fixed list.
- The archive contains aggregate reference tables only. Raw source signals and full per-beat tables must be regenerated locally and must not be added to the public archive.

## Historical pilot reproduction

Run `python scripts/reproduce_historical_pilot.py --external-data-root PATH_TO_PTT_PPG_1.1.0 --report pilot_verification.json`. Obtain the 18 records for subjects 8, 12, 14, 16, 17 and 20 with the provided download script, subject to the source licence. The script independently recomputes the pilot from raw recordings and compares canonical table hashes and all criteria with the aggregate reference JSON. It does not copy archived result tables. An optional `--reference-root PATH_TO_LOCAL_ARCHIVED_OUTPUTS` additionally checks every table entry directly against the historical Parquet files; those full beat tables are not distributed. Only the verification report is written.

The local verification included exact full-table comparisons and hashes of all 54 input files. See HISTORICAL_PILOT_VERIFICATION.json. This corrects the earlier author-review statement that pilot reproduction remained unverified.
